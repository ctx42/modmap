- Before the first phase 1 run, list the saved settings and record each module's CI `TZ` the list lacks (from its Jenkinsfile, both `TZ=UTC` and `TZ = "UTC"` forms) with `:cascade:set -m <module> --env TZ=...`; tests that pin time output fail without it.
- `:cascade:set -m <module>` replaces that module's whole env list: pass every `--env` it needs in one call.
- In phase 1 step 5, also grep every plan module for each released module's current version string (e.g. `<module>:v1.2.3` image tags in configs, compose files, tests); a test tying it to `go.mod` fails only in phase 2.
- Raise image pins to the coming release only after phase 1 passes every module; an untested dependent still starts the pinned image. Then raise, before the gate, every pin a test ties to `go.mod` (`modkit.Ver`, or a test parsing `go.mod` itself): grep the tests of all plan modules, released ones included, never leave one, or phase 2 fails module by module. A module phase 2 only builds still ships such a failing test.
- Never leave uncommitted edits in a released plan module during phase 2: dependents updating to it need a clean tag checkout; park the edit until the run ends.
- `:cascade:set -m <module>` keeps the flags and retries you do not pass; to drop them, `:cascade:set -m <module> -c` first, then set what stays.
- Before the gate, when the changed module drops packages, grep every `excluded` dependency's required version in the module cache for imports of them: `go mod tidy` loads dependencies' tests, so phase 2 fails where phase 1 passed.
- Run every `gomake :cascade:*` target with `GOPRIVATE` naming the private module hosts (`GOPRIVATE=bitbucket.org/vrinf`) unless `go env GOPRIVATE` already does: the lift and phase 2 resolve private modules outside the session, which `goEnv` does not exempt from the checksum database.
- In phase 1 step 5, also grep every plan module for each released module's bare current version (`=vX.Y.Z`, `"vX.Y.Z"`): config pins such as `KEY=vX.Y.Z` name no module, and a test tying them to `go.mod` fails only in CI after the release.
- Before the gate, list every plan module whose commits since its latest tag carry a breaking marker (`!:` subject or `BREAKING CHANGE:` footer): `:bump -u` gives it a new major version. Name each at the gate and release it only on the user's explicit word for that major; else stop.
- A map left out of the session (e.g. its scan fails) leaves its modules unguarded: `:cascade:modfiles` holds only session modules with breaking commits, so grep every `lift.txt` for lifts of out-of-session modules, check each range for breaking markers, and put a breaking one back with `go get -modfile=<abs copy> <mod>@<old>` before phase 1.
- Before phase 1 and again before phase 2, `docker pull` every image tag the plan modules pin (`NEEDS_IMAGE_*`, `C42_BLD_IMG_*`): a local tag built from cached base layers can differ from the registry's CI build (e.g. a newer database extension), so local tests pass while CI fails after the release.
- Run the bare-version grep for every module the plan releases, not only those with images: a plan module's config can pin a released library (e.g. `C42_BLD_GOMAKE_VERSION=vX.Y.Z`) that a test ties to its `go.mod`; raise each such pin to the coming release before the gate.
